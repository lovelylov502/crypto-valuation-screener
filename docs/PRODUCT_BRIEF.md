# Crypto Rediscovery Screener — Product Brief

## 제품 정의

토큰에 귀속되는 펀더멘털은 개선되지만 가격에는 아직 충분히 반영되지 않은 **재발견 전 후보**를 사용자가 직접 필터링하고 검산하는 단일 화면 스크리너다.

## 사용자 목표

1. 필수 데이터 게이트를 통과한 발굴 후보와 관찰 대상을 빠르게 나눈다.
2. 가치·개선·가격 미발견·시장 품질의 4축 근거를 확인한다.
3. `가치 함정`, `재평가 진행 중`, `데이터 보류`, `신규 프로젝트`를 후보와 분리한다.
4. 신뢰도 A/B/C와 실패 게이트를 보고 데이터가 약한 고득점을 걸러낸다.
5. CMC·CoinGecko·DefiLlama 원출처로 이동해 최종 검증한다.

## 핵심 제품 약속

> 단순히 싸 보이는 코인이 아니라, 펀더멘털 개선과 가격 반영 사이에 확인 가능한 간극이 있는 후보만 앞에 둔다.

## 정보 구조

별도 내비게이션이 없는 단일 페이지다.

```text
헤더와 4축 설명
→ 발굴 후보 / 65+ / 데이터 보류 / 전체
→ 검색·신뢰도·리스크·신규 트랙 필터
→ 발견 점수·시총·TVL·P/HR·P/S 범위
→ 결과 수·데이터 coverage·갱신 시각
→ 판정/점수·신뢰도·4축·게이트가 보이는 표
```

## 필수 기능

- 발굴 후보 / 65+ 전체 / 데이터 보류 / 전체 프리셋
- 발견 점수·신뢰도 A/B/C·필수 게이트 사유
- 4축 점수: 가치 30 · 개선 25 · 미발견 25 · 품질 20
- CoinMarketCap Keyless 7/30/60/90일 가격·거래량·canonical ID
- CoinGecko 1년·ATH·ATL 보조 열
- 좀비 숨김, 현재 홀더가치만, 고희석 제외, 신뢰도 B+
- 적격 최근 30일 연환산과 raw TTM을 분리한 holder-value 열, component 경제유형·경고
- 90일 미만 신규 프로젝트 분리
- 별표 관심종목, 열 선택·정렬, 양손잡이 범위, 섹터 다중 선택

## UX 원칙

1. 점수 숫자보다 상태·신뢰도·게이트 실패 이유를 먼저 이해할 수 있어야 한다.
2. 데이터가 빠진 행을 남은 지표로 100점까지 재가중하지 않는다.
3. 가격 하락 자체를 저평가 신호로 표현하지 않는다.
4. 탭과 별도 후보 큐를 추가하지 않고 한 화면의 탐색 흐름을 유지한다.
5. 매수·매도 추천 표현은 쓰지 않는다.

## 성공 조건

- ambiguous parent 그룹은 점수를 받지 않는다.
- 발굴 후보는 모든 게이트와 축별 하한을 통과한다.
- 60일 가격, 유동성, 신뢰도, 게이트 사유가 화면에서 확인된다.
- P/HR은 적격 recent 30d run-rate만 따르며 fee burn·ve/voter/locker·불명확 유형은 raw로만 보인다.
- 검색·범위·섹터·상태 필터를 한 번에 초기화할 수 있다.
- 데스크톱과 모바일에서 가로 스크롤·고정 코인 열이 동작한다.
