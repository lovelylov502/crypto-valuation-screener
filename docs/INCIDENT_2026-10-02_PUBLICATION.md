## 이전 수정이 재발을 막지 못한 이유

9월 30일의 CoinGecko 요청 분할은 실제 403 문제를 해결했다. 그러나 당시 20:11·20:18 KST에 같은 날의 수집 두 번을 통과한 것으로 전체 갱신 문제의 복구를 판단했다. 원천의 이후 변경과 다음 UTC 날짜의 자료를 검증하지 못했다.

23:19 KST의 첫 재발은 Frankencoin의 원천 자산 ID가 `frankencoin`에서 `frankencoin-shares`로 바뀌면서 발생했다. 이후 프로젝트 삭제, 날짜별 보고 누락, 조회 기간에서 빠진 마지막 0 집계, 정의 문구 변경, CMC 목록의 자산·필드 누락이 쌓였다. 기존 공개 검사는 모두 새 수동 검토 대상으로 분류했고, 9월 30일에만 적용되는 검토 기록으로는 처리할 수 없었다.

10월 2일 10:09 KST 실행은 수집 단계가 오류 없이 끝났다고 기록했지만 결과와 보고서가 없었다. 공개 단계는 `collector_did_not_complete`와 `candidate_artifacts_missing`으로 차단했다. 화면은 이 미완료를 ‘변화 0개’로 표시했다. 동일 코드의 Node 22·24 로컬 수집에서는 조기 종료가 재현되지 않았으므로 당시 프로세스 종료의 세부 원인은 확정하지 않았다.

## 계획과 완료 기준

1. 마지막 정상본과 이후 실패 원본을 대조한다. 검증: 최초 실패, 최신 실패, 날짜가 바뀐 수집의 원인이 각각 설명되어야 한다.
2. 현재 원천을 매번 대조하는 처리와 수집 완료 검증을 구현한다. 검증: 원천의 미제공은 정확히 표시하고, 수집 누락·요청 실패·잘못된 자산 연결은 계속 차단해야 한다.
3. GitHub의 단일 공개 경로로 새 수집본을 공개하고 정식 배포한다. 검증: 실제 새 공개본, 후속 수집, 전체 운영 감사와 브라우저 표시를 확인한다.

## 수정

- CMC 목록에서 빠진 기존 자산과 필드가 부족한 응답은 자산 ID로 다시 조회한다. 이전 금액은 복사하지 않는다.
- 프로젝트 제거와 자산 연결 변경은 독립 원천 목록·명시적 ID·새 시세 조회를 대조한다. 원천이 토큰 연결을 철회한 경우에는 연결 미확인과 금액 미제공을 유지한다.
- 수익과 홀더 환원의 누락 날짜는 해당 집계에 선택된 구성원의 개별 원천을 조회한다. ID·이름·parent·정의·중복 집계 상태와 실제 UTC 보고 일수가 맞아야 미제공 상태를 승인한다. 다른 구성원이 포함된 parent 합계나 0으로 누락을 채우지 않는다.
- 정의 변경은 새 정의와 원천의 일치를 확인하되, 경제적 분류의 검토와 배수 계산 보류를 유지한다.
- 검증 근거와 원본 응답을 매번 보관한다. 날짜가 제한된 예외를 추가하거나 기준본을 초기화하지 않는다. 원천 요청 실패, 원천에 있는 값의 누락, 검증되지 않은 변화는 전체 공개를 계속 차단한다.
- 수집 프로세스가 비동기 작업을 기다리는 동안 유지되는 10분 제한과 단계 기록을 추가했다. 비교 완료가 확인되지 않으면 공개할 수 없고, 화면에는 변화 수를 미확인으로 표시한다.
- FWA 배수를 항상 양수로 요구하던 운영 검사를 수정했다. 실제 보고 일수가 부족하면 배수가 비어 있어야 하고, 기간이 완전하면 계산식을 검증한다. 원천 금액과 시세의 누락 검사는 유지한다.
